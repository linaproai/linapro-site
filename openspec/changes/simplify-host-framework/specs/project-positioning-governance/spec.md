## MODIFIED Requirements

### Requirement: 项目定位统一
系统 SHALL 将 `LinaPro` 的统一项目定位定义为”`面向可持续交付的 AI 原生全栈框架`”，并在项目规范、系统元数据、入口文案和仓库说明中保持该定位一致。默认管理工作台 MUST 被表述为可替换入口，而不是产品的唯一边界。用户使用框架时自定义管理工作台 MUST 作为硬约束，而不是可选的未来规划。

#### Scenario: 项目级说明使用统一定位
- **WHEN** 开发者编写或更新项目规范、系统元数据、入口文案或仓库说明
- **THEN** 相关内容使用”`面向可持续交付的 AI 原生全栈框架`”描述 `LinaPro`
- **AND** 不再将 `LinaPro` 定义为”仅一个后台管理系统”或等价表述

#### Scenario: 管理后台能力作为从属能力表述
- **WHEN** 文档、页面说明或系统元数据需要提及菜单、角色、工作区、系统管理等后台能力
- **THEN** 这些能力被表述为 `LinaPro` 的默认管理工作台或内建通用模块
- **AND** 不被表述为 `LinaPro` 的唯一产品边界

#### Scenario: 自定义管理工作台被写成硬约束
- **WHEN** 开发者设计宿主公开 HTTP 契约、插件页面资源或身份启动数据
- **THEN** 契约必须能被非 Vben 管理工作台消费
- **AND** 不得把默认 Vben 工作台的路由 JSON、Vue 组件路径或布局编译结果当作唯一合法客户端
