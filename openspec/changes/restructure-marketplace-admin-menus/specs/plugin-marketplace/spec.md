## ADDED Requirements

### Requirement: 管理工作台必须提供插件市场目录与角色化子菜单

系统 SHALL 在管理工作台侧边栏提供名为插件市场的目录节点（菜单类型目录），并在其下按权限挂载角色化子菜单。发布者权限 MUST 仅看到“我的插件”。管理者权限 MUST 看到“插件列表”与“插件审核”。详情页 MUST 保持隐藏菜单，仅通过列表或审核入口进入。系统 MUST NOT 将发布表单与全量管理列表、审核队列混在同一默认菜单入口中。

#### Scenario: 仅发布者权限的菜单

- **WHEN** 当前用户拥有`market:plugin:publish`且不拥有`market:plugin:review`
- **THEN** 侧边栏在插件市场目录下仅展示“我的插件”
- **AND** 不展示“插件列表”与“插件审核”

#### Scenario: 管理者权限的菜单

- **WHEN** 当前用户拥有`market:plugin:review`
- **THEN** 侧边栏在插件市场目录下展示“插件列表”与“插件审核”
- **AND** 若同时拥有`market:plugin:publish`，还可展示“我的插件”

#### Scenario: 详情不出现在侧边栏

- **WHEN** 用户打开管理工作台侧边栏
- **THEN** 不展示插件市场详情作为可见菜单项
- **AND** 用户仍可通过列表或审核入口进入详情路由

### Requirement: 我的插件页必须展示归属插件状态并支持添加、发布与下架

系统 SHALL 提供“我的插件”页面，仅列出当前用户作为发布者拥有的市场插件，并展示状态信息（至少包括市场状态、最新版本、最新审核状态、可见性、类型与更新时间）。归属过滤 MUST 在服务端数据库查询阶段完成，不得先返回他人插件再由前端隐藏。

该页面 MUST 将“添加插件”与“发布到市场”拆分为独立动作：
- 工具栏 MUST 提供“登记发布者”入口，用于维护当前用户的发布者资料（创建或选择已有发布者）。
- 工具栏 MUST 提供“添加插件”入口；添加成功后插件仅出现在当前用户“我的插件”列表中，MUST NOT 立即出现在对其他用户可见的插件市场目录中。
- “添加插件”抽屉 MUST 支持上传市场包或提交 Git 仓库地址，MUST NOT 将发布者资料登记作为抽屉主表单内容，MUST NOT 在添加入口内直接完成市场上架。
- 上传包方式 MUST 仅要求上传压缩包（及在需要时选择已绑定发布者）；服务端 MUST 自动解压、校验插件目录规范，并从包内`plugin.yaml`解析插件基本信息（至少包括插件 ID、名称、版本与类型），MUST NOT 要求用户手填这些可由包解析的字段。
- Git 仓库方式 MUST 由服务端根据仓库元数据自动识别插件基本信息，MUST NOT 提供可见性选择控件；添加后的 Git 插件默认处于仅归属可见的草稿状态。
- 操作列表 MUST 提供“发布”动作：将归属插件提交到插件市场，且**每次**发布 MUST 进入管理员审核队列；审核通过前 MUST NOT 对其他用户可见。
- 操作列表 MUST 提供“下架”动作：发布者可将已上架插件从市场撤回；下架后插件 MUST NOT 再出现在市场目录中，但仍保留在“我的插件”中，并可再次发起“发布”，且再次发布仍 MUST 经过管理员审核。
- 该页面 MUST NOT 提供独立的“登记 Git 源”工具栏按钮；Git 源登记 MUST 收敛到“添加插件”流程。
- 该页面 MUST NOT 展示顶部关键词/类型/状态搜索栏作为默认主区域内容。

#### Scenario: 发布者只看到自己的插件

- **WHEN** 发布者打开“我的插件”
- **AND** 市场中存在其他发布者的插件
- **THEN** 列表与总数均不包含他人插件
- **AND** 列表项包含可识别的状态字段
- **AND** 页面主区域不展示顶部搜索表单

#### Scenario: 发布者维护发布者资料

- **WHEN** 发布者首次点击“登记发布者”
- **THEN** 系统打开空的发布者资料维护表单
- **AND** 保存成功后绑定为当前用户唯一发布者，并可用于后续添加与发布流程

#### Scenario: 已登记发布者再次打开可编辑回填

- **WHEN** 当前用户已绑定一个发布者资料
- **AND** 再次打开“登记发布者”
- **THEN** 表单回填已有发布者资料
- **AND** 发布者 Key 与其它字段均可修改
- **AND** 保存后更新现有资料，不创建第二份发布者
- **AND** 若修改发布者 Key，系统在目标 Key 未被占用时完成重命名

#### Scenario: 同一用户不得创建多个发布者

- **WHEN** 当前用户已绑定发布者资料
- **AND** 再次发起创建发布者请求
- **THEN** 系统拒绝创建
- **AND** 不新增第二份发布者记录

#### Scenario: 添加插件仅出现在我的列表

- **WHEN** 发布者通过“添加插件”成功登记上传包或 Git 源
- **THEN** 系统保存归属正确的草稿插件与版本元数据
- **AND** 该插件出现在“我的插件”列表
- **AND** 其他用户的市场目录查询不包含该插件

#### Scenario: 上传包自动解析基本信息

- **WHEN** 发布者在“添加插件”中仅上传符合规范的插件压缩包并提交
- **THEN** 服务端解压并校验目录结构
- **AND** 从`plugin.yaml`解析插件 ID、名称、版本与类型等基本信息
- **AND** 页面不要求用户手填上述可解析字段

#### Scenario: Git 添加不选择可见性

- **WHEN** 发布者在“添加插件”中选择 Git 仓库方式
- **THEN** 表单不展示可见性选择
- **AND** 提交后插件以仅归属可见的草稿状态进入“我的插件”

#### Scenario: 发布者发起发布且必须审核

- **WHEN** 发布者在“我的插件”对可发布插件选择“发布”
- **THEN** 系统将对应版本提交管理员审核
- **AND** 审核通过前该插件不对其他用户展示在市场目录中

#### Scenario: 发布者下架后可再次发布

- **WHEN** 发布者对已上架插件选择“下架”
- **THEN** 该插件从市场目录消失但仍在“我的插件”中
- **WHEN** 发布者再次选择“发布”
- **THEN** 系统再次进入管理员审核流程
- **AND** 审核通过前不对其他用户可见

#### Scenario: 发布者为已有插件上传新版本

- **WHEN** 发布者在“我的插件”为已有插件选择新版本并上传压缩包
- **THEN** 服务端从包内清单解析版本信息并保存归属正确的草稿
- **AND** 页面刷新后可在“我的插件”中看到对应状态变化
- **AND** 新版本上架仍须通过“发布”与管理员审核

#### Scenario: 缺少必填项时不得抛未处理异常

- **WHEN** 发布者未填写必填字段或未选择压缩包即提交添加相关表单
- **THEN** 页面展示字段级或消息级校验反馈
- **AND** 浏览器控制台不得因未捕获的必填校验错误中断交互

#### Scenario: 发布者不得修改他人归属的插件或版本

- **WHEN** 发布者使用不属于当前用户的`publisherKey`或`pluginId`添加插件、上传版本包、发布或下架
- **THEN** 系统在任何草稿、版本、审核状态或产物存储写入前拒绝请求
- **AND** 不产生新的产物存储副作用
- **AND** 目标插件与版本状态保持不变

### Requirement: 插件列表页必须向管理者展示全量插件状态

系统 SHALL 提供管理者“插件列表”页面，展示市场中全部插件的状态信息，并支持筛选与进入详情。该页面 MUST 要求`market:plugin:review`权限。系统 MUST NOT 在该页面混入面向发布者的完整发布向导作为主流程。

#### Scenario: 管理者查看全量状态

- **WHEN** 管理者打开“插件列表”
- **THEN** 列表可包含不同发布者的插件
- **AND** 每项展示市场状态、最新版本、审核相关状态摘要与更新时间

#### Scenario: 发布者不能访问管理列表 API

- **WHEN** 仅拥有`market:plugin:publish`的用户请求管理者全量插件列表
- **THEN** 系统拒绝该越权请求
- **AND** 响应不得返回他人插件投影

### Requirement: 插件审核页必须提供待审队列与审核决策

系统 SHALL 提供“插件审核”页面，默认展示待审核或审核中的版本队列。管理者选中版本后，系统 MUST 通过标准审核抽屉展示产物摘要、风险明细与文档完备性，并允许管理者通过或拒绝。审核入口 MUST NOT 仅依赖手动输入`pluginId`才能看到待审数据；`pluginId`可作为筛选条件。审核写操作 MUST 要求`market:plugin:review`权限。

#### Scenario: 默认加载待审队列

- **WHEN** 管理者打开“插件审核”且不输入 pluginId
- **THEN** 系统展示处于已提交或审核中状态的版本列表
- **AND** 列表包含插件 ID、版本、类型与提交/更新时间

#### Scenario: 审核抽屉展示当前版本的风险明细

- **WHEN** 管理者从待审队列选择一个版本进行检查
- **THEN** 系统在审核抽屉中展示该版本的清单、文档完备性与风险明细
- **AND** 先前关闭的其他版本异步检查结果不得覆盖当前抽屉内容

#### Scenario: 管理者通过或拒绝版本

- **WHEN** 管理者选中一个待审版本并提交通过或拒绝决策
- **THEN** 系统更新该版本审核状态
- **AND** 通过时按既有市场规则发布不可变版本并刷新读模型
- **AND** 拒绝时保留审核意见且不发布该版本

#### Scenario: 发布者不能审核

- **WHEN** 仅拥有`market:plugin:publish`的用户调用审核决策接口
- **THEN** 系统拒绝该请求
- **AND** 版本审核状态保持不变

### Requirement: 市场管理页路由跳转必须使用有效工作台路径

系统 SHALL 保证插件市场管理页面之间的路由跳转使用宿主菜单解析后的顶级`/plugin-marketplace/...`有效路径。从列表进入详情、从详情返回列表或“我的插件”时，MUST NOT 导航到缺少`/plugin-marketplace`目录段的无效`path`而进入`404`。

#### Scenario: 从我的插件进入详情再返回

- **WHEN** 发布者从“我的插件”打开某插件详情
- **AND** 在详情页选择返回
- **THEN** 进入有效的“我的插件”或列表页面
- **AND** 不展示 404 页面

### Requirement: 插件详情下载必须遵循独立下载权限

系统 SHALL 将插件详情读取与产物下载拆分为独立权限。详情页可以使用`market:plugin:view`读取可见内容；下载按钮与下载会话创建、查询和内容读取`API` MUST 要求`market:plugin:download`权限，并继续执行发布状态、可见性与请求人边界校验。

#### Scenario: 无下载权限用户不得触发下载

- **WHEN** 用户拥有`market:plugin:view`但不拥有`market:plugin:download`并打开插件详情
- **THEN** 页面不展示下载动作
- **AND** 用户直接调用下载会话创建、查询或内容读取`API`时系统拒绝请求
- **AND** 响应不得返回产物内容或可用于读取产物的会话信息

## REMOVED Requirements

### Requirement: 扁平 extension 下的市场目录与一体 Console 作为默认管理入口

**Reason**: 扁平`Plugin Marketplace`目录页与`Marketplace Console`发布审核一体页无法表达发布者/管理者角色边界，且交互上把发布与审核、消费目录混在一起。

**Migration**: 使用插件市场目录下的“我的插件”“插件列表”“插件审核”替代；旧 path 在菜单同步后不再作为默认可见入口，实现阶段删除或停用对应菜单声明并迁移 E2E。
