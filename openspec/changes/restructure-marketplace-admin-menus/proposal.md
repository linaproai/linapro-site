## Why

当前插件市场管理工作台把目录、发布与审核混在`extension`下的扁平菜单和单页 Console 中，发布者与管理者看到的入口、列表范围和操作边界不清晰。需要按角色拆分菜单与页面，让发布者只管理自己的插件，管理者可全局查看与审核，形成可理解、可授权的后台信息架构。

## What Changes

- 在管理工作台新增**插件市场**菜单目录（目录节点），不再把市场页面直接挂在`extension`下与普通插件管理平铺。
- **发布者权限**仅可见一个菜单：**我的插件**。
  - 列表仅展示当前用户作为发布者拥有的插件及其状态（市场状态、最新版本、审核状态、可见性等）。
  - 同一页面支持发布新插件（创建/绑定发布者、新建插件草稿、上传版本包、提交审核）。
- **管理者权限**可见两个菜单：
  - **插件列表**：展示市场中全部插件的状态信息（可筛选、可看详情；不混入发布表单）。
  - **插件审核**：对待审/审核中版本进行检查与通过/拒绝，不依赖手输 pluginId 作为唯一入口。
- **BREAKING（工作台入口）**：移除或替换现有`Plugin Marketplace` / `Marketplace Console`菜单路径与页面职责；旧`catalog`消费目录与`console`发布审核一体页不再作为默认管理入口。
- 同步调整`plugin.yaml`菜单、权限标签绑定、前端页面拆分、列表查询与发布写操作的归属校验，以及中英文`i18n`与`E2E`。
- 修复既有路由前缀问题（页面跳转必须落到顶级`/plugin-marketplace/...`完整路径或宿主菜单解析后的真实`path`），以及发布表单缺少字段校验导致的未捕获错误。

## Capabilities

### New Capabilities

- 无。

### Modified Capabilities

- `plugin-marketplace`：管理工作台菜单改为“插件市场”目录下的角色化入口；发布者仅见“我的插件”，管理者见“插件列表”与“插件审核”；列表与审核的数据范围、页面职责与权限边界按角色收敛。

## Impact

- 影响`apps/lina-plugins/linapro-plugin-marketplace/plugin.yaml`菜单树（目录 + 子菜单）、`manifest/i18n`菜单与页面文案、前端`frontend/pages/*`页面拆分与路由元数据。
- 影响市场列表/发布相关`API`的查询与写入语义：发布者“我的插件”必须在服务端按发布者归属过滤；发布草稿、上传版本包和提交审核必须绑定当前用户，并在写入产物前校验发布者与插件归属；管理者“插件列表”可查全量状态（仍受数据权限与可见性规范约束）。
- 影响权限配置：继续沿用并明确区分`market:plugin:publish`（发布者）、`market:plugin:review`（管理者列表与审核）、`market:plugin:view`（详情读取）与`market:plugin:download`（详情下载按钮和下载`API`），避免发布者越权看到或修改他人插件，也避免无下载权限用户触发产物读取。
- 影响 E2E 与前端单测：`hack/tests/e2e`、`MarketplacePage`、fixtures 中的菜单路径与断言。
- `i18n`影响：菜单名、页面标题、空态与操作文案需中英文同步。
- 数据权限影响：发布者列表必须在 DB 查询阶段按`owner_user_id`/发布者归属过滤，不得先查全量再前端过滤。
- 缓存一致性：若读模型含全量投影，归属过滤条件必须进入查询；本变更不改变下载统计权威源。
- 开发工具跨平台：无影响（不修改 Makefile / linactl）。
