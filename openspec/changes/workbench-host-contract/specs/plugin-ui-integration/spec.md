## MODIFIED Requirements

### Requirement:插件页面支持多种宿主集成模式
系统 SHALL 支持三种插件页面集成模式：`iframe`、新标签页导航和宿主嵌入式挂载。这些模式 MUST 作为通用打开方式出现在导航资源中，而不是默认工作台的组件名或 query 约定。

#### Scenario:以 iframe 模式集成插件页面
- **当** 插件菜单声明使用 `iframe` 模式的页面时
- **则** 宿主在通用导航资源中给出 iframe 打开方式与目标地址
- **且** 管理工作台在自己的壳内用 iframe 加载该地址
- **且** 宿主仍通过 LinaPro 菜单、权限和导航管理页面入口

#### Scenario:以新标签页模式集成插件页面
- **当** 插件菜单声明使用新标签页模式的页面时
- **则** 通用导航资源使用外链或新窗口打开方式
- **且** 点击菜单时工作台在新浏览器标签页中打开对应的插件页面
- **且** 原始宿主工作区导航状态不受影响

#### Scenario:以宿主嵌入模式集成插件页面
- **当** 插件页面声明宿主嵌入式挂载模式时
- **则** 通用导航资源提供内嵌打开方式与前端入口资源地址
- **且** 默认工作台将入口加载到指定容器中
- **且** 插件内部可使用任何前端框架
- **且** 前端入口必须满足当前工作台定义的挂载契约
- **且** 宿主公开包不得出现默认工作台的动态页组件路径

### Requirement:宿主管理插件前端资产
系统 SHALL 根据插件类型托管前端资产，并为每种页面集成模式提供稳定的资产访问 URL。约定目录发现 MAY 继续用于定位源文件，但写入宿主契约的 MUST 是通用页面资源。

#### Scenario:源码插件参与宿主构建
- **当** 源码插件按约定提供前端资产时
- **则** 这些前端资产参与默认工作台前端构建管线
- **且** 源码插件的宿主嵌入页面必须使用真实的前端源文件实现，而非仅声明式 JSON 页面描述
- **且** 这些源文件默认放置在 `frontend/pages/` 下，可按约定目录发现
- **且** 宿主同步出的导航资源只包含通用页面字段
- **且** 最终资产与默认工作台前端一起嵌入后端二进制文件

#### Scenario:动态插件提供前端资产
- **当** 安装了带资产的运行时 `wasm` 插件时
- **则** 宿主提取并托管插件的静态前端资产
- **且** 宿主为插件生成稳定的静态资产路径
- **且** 未正确准备前端资产的插件页面无法启用
- **且** 导航资源使用该资产地址与内嵌打开方式，而不是工作台组件路径

#### Scenario:动态插件前端资产可来自嵌入式资源声明
- **当** 动态插件作者通过 `go:embed` 声明 `frontend` 目录资产时
- **则** 构建器必须从嵌入式文件系统提取前端静态资产并写入运行时快照
- **且** 宿主继续从该运行时快照提供统一托管资产 URL
- **且** 宿主不需要通过 guest 运行时方法逐项读取前端资产内容

### Requirement:插件页面参与宿主路由和 generation 感知

系统 SHALL 将已启用的插件页面纳入当前用户可访问的通用导航资源，并在插件 generation 变更时保护当前用户体验。插件注册表状态变更后，宿主 MUST 在当前登录会话内重建可访问导航资源；管理工作台 MUST 根据新的通用导航资源重建自己的动态路由。当当前路由在新路由表中仍可访问且不需要立即应用插件页新 meta 时，工作台 MUST 静默完成该重建，不得对当前宿主页面执行强制 rematch 导航导致页面组件无故 remount。

#### Scenario:宿主生成插件页面路由

- **当** 已启用的插件声明可见菜单和页面入口时
- **则** 宿主将这些入口加入当前用户的通用导航资源
- **且** 默认工作台据此编译动态路由
- **且** 插件页面可见性仍由 LinaPro 角色权限控制

#### Scenario:插件向左侧导航菜单插入顶级入口

- **当** 已启用的插件声明左侧导航菜单的顶级入口时
- **则** 工作台在左侧菜单顶部附近显示该插件入口
- **且** 点击入口在主内容区域打开插件标签页
- **且** 页面内容清晰指示该入口来自插件扩展机制

#### Scenario:当前会话中启用插件后立即刷新左侧导航菜单

- **当** 管理员在已登录会话中启用已安装但当前禁用的源码插件时
- **则** 宿主刷新通用导航资源，工作台刷新动态路由和左侧导航菜单，无需重新登录
- **且** 插件新增的顶级菜单入口立即可见
- **且** 当前页面保持在宿主工作区环境内

#### Scenario:在插件管理页启停插件时静默刷新路由

- **当** 管理员停留在插件管理页并启用或禁用某个插件，且插件管理页路由在刷新后仍可访问时
- **则** 工作台重建可访问路由，使插件菜单入口即时增减
- **且** 工作台不得因该次同步对插件管理页执行 force rematch 导航
- **且** 插件管理页组件状态（筛选、滚动位置、列表交互）保持不被整页 remount 清空

#### Scenario:当前路由因插件禁用而失效时离开失效页

- **当** 当前登录用户停留在某插件页面，且该插件在当前会话中被禁用或卸载导致路由不再可访问时
- **则** 工作台在重建可访问路由后将用户导航到安全回退路径
- **且** 不得继续展示已失效的插件页面实例作为可操作工作区

#### Scenario:插件状态变更后当前会话重新获得焦点

- **当** 当前登录会话外的其他操作更改了插件启用状态，且当前浏览器标签页重新获得焦点时
- **则** 工作台自动重新同步插件相关动态路由和左侧导航菜单
- **且** 已启用插件的入口重新可见
- **且** 已禁用插件的入口及时隐藏

#### Scenario:当前用户停留在插件页面时发生热升级

- **当** 当前用户正在访问插件页面且该插件升级到新 generation 时
- **则** 工作台显示提示告知用户插件已更新，当前页面应刷新
- **且** 不在该插件页面上的用户不被强制中断

#### Scenario:刷新后当前插件页面切换到新 generation

- **当** 当前用户停留在动态插件页面且该插件已完成 generation 切换时
- **则** 用户点击"刷新当前页面"后，工作台先为当前登录用户重建可访问菜单和动态路由
- **且** 工作台不强制先将用户导航到其他工作区页面
- **且** 当前插件页面随后以新 generation 资产重新挂载并更新相关标签页元数据

#### Scenario:热升级后非插件页面上的用户不受影响

- **当** 动态插件完成热升级但当前用户未停留在该插件页面时
- **则** 工作台不显示插件刷新提示
- **且** 工作台不因该升级强制中断当前非插件页面的浏览
- **且** 用户仅在稍后进入插件页面时才开始使用新 generation 资产
