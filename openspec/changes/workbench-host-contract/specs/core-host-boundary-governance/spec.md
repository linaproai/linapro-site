## MODIFIED Requirements

### Requirement:lina-core 核心宿主能力保持通用边界
系统 SHALL 将 `apps/lina-core` 视为框架的核心宿主服务，优先保证通用模块接口能力、组件能力、系统治理能力和插件扩展能力的稳定性和可复用性。宿主公开 HTTP 契约 MUST 能被非默认管理工作台消费，MUST NOT 按 Vben 路由 JSON、Vue 单文件组件路径或默认壳布局组件名设计。

#### Scenario:页面需求仅影响工作台展示
- **当** 需求仅变更表格列、筛选项、树选择器、工作台聚合、路由组装或其他特定页面展示结构时
- **则** 系统优先通过工作台适配接口或前端适配层完成变更
- **且** 不因该页面需求直接修改 `lina-core` 的核心领域契约、通用服务语义或存储模型

#### Scenario:计划修改核心接口或模型
- **当** 开发者因某前端页面需求计划修改 `lina-core` 的核心接口、领域模型或持久化结构时
- **则** 修改必须能够证明其服务于框架级通用能力而非单个页面表单
- **且** 如果无法证明，应回退到工作台适配实现方案

#### Scenario: 宿主公开导航契约被非 Vben 壳消费
- **当** 用户使用自定义管理工作台拉取当前用户导航和插件页面资源时
- **则** 该壳无需理解`#/views`、`IFrameView`或`system/plugin/dynamic-page`
- **且** 壳使用通用打开方式、资源地址和能力标志完成启动

### Requirement:工作台适配接口必须显式分类
系统 SHALL 将明确面向某一套工作台编译结果的输出（如 Vben 路由记录、壳组件路径、树选择器的页面专用形状）放在该工作台内，而不是放进`lina-core`公开 HTTP 契约。宿主可以向任意工作台提供通用导航资源、身份、权限和可选壳偏好；Vben 路由编译 MUST 由默认工作台完成。

#### Scenario:接口返回工作台组装数据
- **当** 默认工作台需要菜单路由、树选择器节点或下拉选项等工作台组装数据时
- **则** Vben 路由记录由`lina-vben`编译产生
- **且** 宿主公开导航接口不得把自己描述为 Vben 路由模型

#### Scenario:通用领域能力被多个工作台复用
- **当** 能力需要被不同工作台或不同访问方式同时消费时
- **则** 系统优先保留稳定的通用领域接口
- **且** 不同工作台所需的菜单、路由、展示结构或聚合视图通过工作台自己的适配层组装
