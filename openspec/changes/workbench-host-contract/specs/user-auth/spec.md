## MODIFIED Requirements

### Requirement:登录后返回用户信息

用户登录成功后，系统 SHALL 返回用户身份、角色、权限标识和落地路径，以及组织、租户等可选能力是否启用的明确标志。系统 MUST NOT 在身份接口中返回菜单树。`homePath` MUST 从用户当前可访问的启用导航资源中解析，优先选择适合作为落地页的稳定内部路由；当工作台等默认菜单不可用时，`homePath` MUST 指向第一个可用的可导航内部路由，而不得返回已停用菜单路径。若用户没有任何可导航内部资源，系统 MAY 返回安全兜底路径（例如个人中心）。

#### Scenario:登录成功返回用户信息
- **当** 用户使用正确的用户名密码登录时
- **则** 系统返回 userId、username、realName、email、avatar
- **且** 系统返回 roles 字段，包含用户所有角色的 key 列表
- **且** 系统不得返回 menus 字段或等价菜单树
- **且** 系统返回 permissions 字段，包含用户拥有的权限标识列表
- **且** 系统返回组织与租户等能力是否启用的明确标志
- **且** 系统返回 homePath 字段，指定用户的首页路径，且该路径对应启用且可导航的资源（或安全兜底路径）

#### Scenario:超级管理员登录
- **当** admin 角色用户登录时
- **则** 系统按超级管理员规则计算 homePath 与权限
- **且** roles 包含 "admin"
- **且** permissions 包含 "*:*:*" 表示拥有所有权限
- **且** 身份响应仍不得包含菜单树

#### Scenario:普通用户登录
- **当** 非超级管理员用户登录时
- **则** 系统根据用户角色查询 sys_role_menu 获取菜单 ID 列表
- **且** 系统根据该列表计算 homePath 与 permissions
- **且** 系统过滤掉状态为停用（status = 0）的菜单
- **且** 系统过滤掉隐藏的菜单（visible = 0）后仍不得把菜单树放进身份响应

#### Scenario:用户登录时无角色
- **当** 用户登录时未分配任何角色
- **则** 系统不返回菜单树
- **且** roles 为空数组
- **且** permissions 为空数组

#### Scenario:用户所有角色被停用
- **当** 用户的所有角色都被停用时
- **则** 系统不返回菜单树
- **且** roles 为空数组
- **且** permissions 为空数组

#### Scenario:工作台菜单停用时 homePath 避开工作台
- **WHEN** 用户可访问导航中不包含工作台叶子资源（例如分析页路径已停用）
- **AND** 仍存在其他可导航内部资源
- **THEN** 系统返回的 `homePath` 不得为已停用的工作台路径
- **AND** `homePath` 为顺序中第一个可导航内部路由

## REMOVED Requirements

### Requirement:菜单树结构
**Reason**: 身份接口不再返回菜单树。导航资源改由通用导航契约提供，默认工作台负责编译路由。
**Migration**: 客户端改调通用导航资源接口，并在工作台侧编译路由。

## ADDED Requirements

### Requirement: 工作台不得从菜单路径猜测可选能力

系统 SHALL 通过明确能力标志表达组织管理和租户管理是否启用。默认工作台 MUST NOT 通过菜单 path、name 或`Tenant`前缀推断多租户壳行为。

#### Scenario: 登录启动租户壳

- **WHEN** 用户完成登录且租户能力已启用
- **THEN** 工作台根据身份或能力接口中的明确标志启用租户相关壳行为
- **AND** 不得因为某个菜单名以`Tenant`开头而打开租户壳

#### Scenario: 仅存在名称相似的普通菜单

- **WHEN** 租户能力未启用
- **AND** 用户可访问一个路径或名称包含`tenant`的普通菜单
- **THEN** 工作台不得因此启用租户管理壳
