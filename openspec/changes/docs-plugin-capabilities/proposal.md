## Why

官网现有插件系统文档（`5000-plugin-system/`）介绍了插件治理主链、生命周期、目录结构和`pluginhost`注册机制，但缺少对主框架向插件暴露的基础能力服务（`capability.Services`）的系统性介绍。插件开发者在使用`registrar.Services()`获取`Config()`、`Auth()`、`TenantFilter()`等服务时，缺乏架构层面的设计说明，难以理解各服务的定位、边界和协作关系。

## What Changes

- 在`apps/lina-site/docs/docs/2000-components/5000-plugin-system/9000-capabilities/`下按父领域能力维护插件能力文档
- 创建总览文档`9000-capabilities.md`，覆盖`capability.Services`、`pluginhost.Services`、`AdminServices`和动态`hostServices`的可用能力矩阵
- 以领域能力维度组织文档，`AI`子能力、`Plugins().Config()`、`Plugins().State()`、`Plugins().Lifecycle()`、`TenantFilter()`等子能力在父领域文档内介绍，不单独拆页
- 补齐用户、字典、文件与存储、数据记录、基础设施、动态`Runtime`、任务与定时、外部网络、分布式锁等已暴露给插件但原目录未单独覆盖的能力
- 配置管理保留关系介绍页，说明`Plugins().Config()`、`HostConfig()`、`Admin().Config()`、动态`config.get`和`hostconfig.get`之间的领域边界
- 中文主稿确认后同步英文`i18n`镜像
- `orgcap.Service`和`tenantcap.Service`文档额外包含提供方`Provider`实现指引

## Capabilities

### New Capabilities

- `plugin-capabilities-overview`：插件能力总览，包含架构图、获取方式、普通能力、源码插件专属能力、管理命令、动态`hostServices`和按场景选型指南
- `plugin-capability-ai`：`AI`领域能力，包含文本、图片、向量、音频、视觉、文档、安全和视频子能力
- `plugin-capability-apidoc`：`APIDocService`架构设计——API文档本地化服务的设计动机、操作键构建机制和在请求链路中的位置
- `plugin-capability-auth`：`AuthService`架构设计——认证Token交接服务的两阶段模型、模拟令牌治理边界
- `plugin-capability-users`：用户领域能力——用户投影、搜索、可见性校验和用户状态管理命令
- `plugin-capability-bizctx`：`BizCtxService`架构设计——业务上下文投影服务的设计约束和与请求链路的关系
- `plugin-capability-cache`：`CacheService`架构设计——插件作用域缓存的隔离策略和过期机制
- `plugin-capability-dict`：字典领域能力——字典标签解析和刷新命令
- `plugin-capability-config`：配置管理能力关系介绍——插件配置、宿主配置和运行时配置管理的入口差异
- `plugin-capability-i18n`：`I18nService`架构设计——运行时翻译服务的设计和翻译键命名约定
- `plugin-capability-manifest`：`ManifestService`架构设计——插件清单资源服务的路径语义和资源管线边界
- `plugin-capability-files-storage`：文件与存储领域能力——宿主文件投影、文件删除命令和动态`storage`服务
- `plugin-capability-notify`：`NotifyService`架构设计——通知服务的发布模型和收件箱分类
- `plugin-capability-org`：`orgcap.Service`架构设计——组织能力的消费侧只读接口和提供方`Provider`扩展机制
- `plugin-capability-plugins`：插件治理领域能力——注册表投影、插件配置、启用状态、能力提供方状态和生命周期编排
- `plugin-capability-recordstore`：数据记录领域能力——动态`data`服务和`guest.RecordStore()`受治理表访问
- `plugin-capability-route`：`RouteService`架构设计——动态路由元数据服务的设计和与动态插件的关系
- `plugin-capability-session`：`SessionService`架构设计——在线会话管理服务的设计和会话投影模型
- `plugin-capability-tenant`：`tenantcap.Service`架构设计——租户能力的消费侧接口和提供方`Provider`/`Resolver`扩展机制
- `plugin-capability-infra`：基础设施能力——组件状态、状态刷新和动态`service: infra`
- `plugin-capability-runtime`：动态`Runtime`能力——动态插件日志、插件作用域运行状态、宿主时间、`UUID`和节点身份
- `plugin-capability-jobs-cron`：任务与定时能力——任务投影、任务管理命令、源码插件`Cron()`和动态`cron.register`
- `plugin-capability-network`：外部网络能力——动态`network.request`受治理出站请求
- `plugin-capability-lock`：分布式锁能力——动态`lock.acquire`、`lock.renew`和`lock.release`

### Modified Capabilities

（无现有能力的需求变更）

## Impact

- 新增和重组文件：`apps/lina-site/docs/docs/2000-components/5000-plugin-system/9000-capabilities/`目录下按领域能力组织的`.md`文件
- 侧边栏自动发现：`sidebars.ts`使用`autogenerated`，新增目录会自动纳入`docsSidebar`
- 与现有文档的关联：源码插件文档中已提及的`Services()`、`Plugins().Config()`、`HostConfig()`、`Manifest()`等内容将在新文档中得到深入展开，新文档将与现有文档互相链接
- 无代码变更、无依赖变更、无破坏性影响
