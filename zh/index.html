面向可持续交付的 AI 原生全栈框架

把 AI 作为全栈研发的核心生产力，以高效、易用、可维护的方式帮助每一位开发者交付生产级应用

快速开始 →GitHub →

框架特点

让 AI 生产力随迭代复利增长，让交付质量在产品规模扩大后依然可验证、可演进。

AI 原生研发工作流

从探索、提案、实现到审查归档，AI 始终基于已验证规范推进，需求、代码与测试持续对齐，减少架构漂移。

模块级松耦合设计

业务模块以接口协作、独立演进，可按需启用、替换或下线，不把局部变化扩散成全栈改造，长期保持清晰边界。

双模式可插拔运行时

源码插件适合深度扩展，WASM 插件支持运行时热加载；两类插件都在隔离沙箱中运行，资源按命名空间管理。

全栈契约一体化

服务 API、OpenAPI 文档、权限元数据与 Vue 工作台共享同一模型，宿主和插件接口自动汇入接口文档并可在线调试。

框架级国际化治理

宿主、源码插件、动态插件与接口文档共用翻译资源，新增语言以资源文件为准，并内置缺失检查、来源诊断与缓存。

企业级治理开箱即用

JWT、声明式 RBAC、权限标签、字段脱敏、强制下线、IP 与设备指纹审计直接内置，权限变更可秒级生效。

原生分布式架构

权限拓扑同步、分布式锁、键值缓存均原生集群感知；从单节点到完整集群，无需任何架构改造即可平滑扩展。

可追踪的升级治理

框架与源码插件升级走显式流程，升级前校验风险，升级中同步结构、菜单、权限与治理资源，避免隐性版本漂移。

生产就绪开箱即用

核心服务、官方插件与功能完备的管理工作台开箱即用；不必从零搭建基础设施，第一天就能专注业务本身。

可组合的全栈技术架构

每一层都独立设计、严守松耦合原则；业务模块可按需启用或下线，不会牵动整个技术栈。

01

核心宿主服务

apps/lina-core

通用 Go 后端运行时，统一承载 API 契约、服务治理、认证鉴权、权限管理与插件生命周期等通用能力。

02

管理工作台

apps/lina-vben

生产就绪的 Vue 3 工作台，覆盖每一项内置能力的参考 UI 实现；可直接扩展，也可整体替换。

03

双模式插件系统

apps/lina-plugins

源码插件无限扩展与WASM动态热加载，内置沙箱安全权限控制，资源严格隔离；无需触碰宿主，即可扩展或覆盖任意能力。

04

AI 原生研发工作流

openspec/

规范优先的结构化工作流，让 AI、人类与代码库在每一次迭代中始终步调一致。

规范驱动的 AI 研发闭环

以增量规范和强制 E2E 测试串起研发闭环，让 AI 始终在已验证的基线之上持续推进。

STAGE 01

探索

动手之前先把问题域摸清楚，把可选路径一一摆上台面。

STAGE 02

提案

把意图沉淀为增量规范文件，并锚定明确的验收条件。

STAGE 03

实现

AI 依据规范完成实现，并同步补齐对应的 E2E 测试。

STAGE 04

审查

人类在关键节点对规范、代码与测试逐项审查、严格把关。

STAGE 05

归档

通过验证的规范并入基线，下一次迭代便从坚实的地基起步。

开箱即用的管理工作台

内置模块可直接构建业务，也可通过插件扩展或替换，并统一接入实时生效的 RBAC 权限体系。

工作台概览
用户与角色权限
业务模块管理
监控与审计

三条命令，立即上手

一键安装脚本覆盖 macOS / Linux / Windows，常用任务统一收敛到 Make 入口，默认管理工作台登录即用。

INSTALL
curl -fsSL https://linapro.ai/install.sh | bash
INITIALIZE
make init confirm=init
make mock confirm=mock   # optional demo data
DEVELOP
make dev
# Workspace: http://localhost:5666
# API:       http://localhost:8080
默认账号： admin / admin123
