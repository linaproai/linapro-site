  • I18N国际化

概述​

LinaPro内置了完整的国际化运行时，支持在请求级别动态切换语言，宿主和插件的语言资源统一管理，插件启用后语言包自动合并。

配置​

在config.yaml中配置国际化行为：

i18n:
  # 默认语言（请求未携带语言标识时使用）
  default: zh-CN
  # 是否开启多语言；关闭时前端隐藏语言切换按钮
  enabled: true
  # 语言列表（决定前端切换菜单的顺序和显示名称）
  # 注释某个语言即可停用
  locales:
    - locale: en-US
      nativeName: English
    - locale: zh-CN
      nativeName: 简体中文
    - locale: zh-TW
      nativeName: 繁體中文

目录结构​

宿主语言资源位于manifest/i18n/目录下：

apps/lina-core/manifest/i18n/
├── zh-CN/
│   ├── framework.json         # 框架基础文案
│   ├── menu.json              # 菜单名称
│   ├── dict.json              # 字典类型和字典数据名称
│   ├── config.json            # 系统参数相关文案
│   ├── error.json             # 错误信息
│   ├── job.json               # 定时任务相关文案
│   ├── notify.json            # 通知相关文案
│   ├── role.json              # 角色相关文案
│   ├── plugin.json            # 插件相关文案
│   ├── artifact.json          # 构建产物相关文案
│   ├── public-frontend.json   # 前端公共文案
│   └── apidoc/
│       ├── common.json        # 公共接口文档翻译（分页、时间戳等公共字段）
│       └── core-api-*.json    # 各模块接口文档翻译
├── en-US/
│   └── （与 zh-CN 相同结构，英文翻译）
└── zh-TW/
    └── （与 zh-CN 相同结构，繁体中文翻译）

语言包格式​

语言包使用JSON格式，支持嵌套结构（推荐）或扁平点分隔键：

{
  "menu": {
    "dashboard": {
      "title": "工作台"
    },
    "iam": {
      "title": "权限管理",
      "user": {
        "title": "用户管理"
      }
    }
  },
  "framework": {
    "description": "面向可持续交付的 AI 原生全栈框架"
  }
}

扁平键等价写法：

{
  "menu.dashboard.title": "工作台",
  "menu.iam.title": "权限管理"
}

框架在加载时会将嵌套JSON规范化为扁平键，两种格式混用时扁平键优先级更高。

插件国际化​

每个插件在自己的manifest/i18n/目录下维护语言包，插件启用后宿主自动合并插件的语言资源：

apps/lina-plugins/content-article/manifest/i18n/
├── zh-CN/
│   ├── content-article.json         # 插件运行时语言包
│   └── apidoc/
│       └── plugin-api-article.json  # 插件接口文档翻译
└── en-US/
    └── content-article.json

插件语言包文件使用插件ID命名（kebab-case），避免与宿主和其他插件的键名冲突：

{
  "plugin": {
    "content-article": {
      "article": {
        "title": "文章管理",
        "status": {
          "draft": "草稿",
          "published": "已发布"
        }
      }
    }
  }
}

添加新语言​

添加新语言只需三个步骤，不需要修改任何Go代码、SQL或前端TypeScript文件：

第一步：在config.yaml中注册语言

i18n:
  locales:
    - locale: ja-JP
      nativeName: 日本語

第二步：创建语言资源目录

mkdir -p apps/lina-core/manifest/i18n/ja-JP/apidoc

第三步：创建翻译文件

在manifest/i18n/ja-JP/下创建对应的JSON翻译文件，复制中文或英文版本作为模板，翻译各条目内容。

重启服务后，管理工作台语言切换菜单中会自动出现日文选项。

翻译缓存管理​

运行时语言包在首次请求时加载到内存缓存，修改翻译文件后需要使缓存失效才能生效。

重启服务（开发环境）：

make stop && make dev

运行时缓存失效（生产环境，无需重启）：

框架提供了按范围失效的API，在管理工作台的系统接口中可以触发。缓存失效的范围粒度：

范围说明
特定语言只失效指定locale的缓存
特定插件只失效指定插件的翻译缓存
宿主全量失效宿主所有语言的缓存
tip

不要无理由清空所有语言和所有扇区的翻译缓存，这会导致短暂的翻译抖动。按最小必要范围失效，减少对用户的影响。

前端语言切换​

前端管理工作台在页面右上角提供语言切换控件，点击后立即切换界面语言。语言选项来自i18n.locales配置。

当i18n.enabled: false时，前端隐藏语言切换控件，所有文案使用i18n.default指定的默认语言。

接口文档翻译​

接口文档（/api.json）的描述文本也支持多语言翻译（没有翻译时默认为英文），翻译文件放在apidoc/子目录下：

// manifest/i18n/zh-CN/apidoc/core-api-article.json
{
  "plugins": {
    "content-article": {
      "article": {
        "list": {
          "summary": "文章列表",
          "description": "分页查询文章列表，支持按状态筛选",
          "params": {
            "page": "页码",
            "pageSize": "每页数量"
          }
        }
      }
    }
  }
}

en-US的接口文档翻译目录通常保留为空占位，以英文源码注释作为默认文案。

语言代码规范​

LinaPro使用标准IETF BCP 47语言代码，例如：

语言代码
简体中文zh-CN
繁體中文zh-TW
英文en-US
日文ja-JP
韩文ko-KR

配置文件的目录名、config.yaml中的locale字段、前端locale参数均使用这套代码，保持一致。
