# OpenSpec 工作流

LinaPro 把研发工作流本身视为框架的一部分。

## 闭环

```text
Explore -> Propose -> Implement -> Review -> Archive
```

## 每个阶段在做什么

### Explore

先理解问题空间、检查代码边界、梳理未知项，再开始实现。

### Propose

创建变更并沉淀：

- `proposal.md`
- `design.md`
- `tasks.md`
- capability specs

这一步把模糊意图变成明确契约。

### Implement

按经过确认的任务执行，而不是在代码库里随意穿梭式实现。

### Review

在完成前检查行为、边界、回归风险和规范一致性。

### Archive

把完成的变更沉淀为新的基线知识，确保后续工作从更新后的真相源出发。

## 这为什么对 AI 时代重要

如果没有可持续的工件轨迹，AI 系统就会持续丢失上下文，团队也会在每几个会话后重新做一次对齐。

OpenSpec 让 LinaPro 可以做到：

- 决策成为可持续工件
- 需求保持可测试
- 设计意图可检查
- 下一次 AI 辅助变更从共享基线开始

这也是为什么 LinaPro 不只是一个运行时技术栈。工作流本身就是产品的一部分。
