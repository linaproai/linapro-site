# Core Host

`apps/lina-core` is the GoFrame-based host service of LinaPro.

## What the host owns

- host-side RESTful APIs for system management and platform governance
- database migrations and seed data
- runtime configuration
- plugin loading and lifecycle coordination
- core scheduled-job infrastructure

## Why the host boundary matters

LinaPro does not treat the host as a catch-all business layer.

The host should keep:

- stable cross-cutting platform capabilities
- contracts that other layers depend on
- governance primitives that must stay authoritative

Optional business modules belong in plugins whenever possible.

## Key directories

```text
api/                API DTOs and route contracts
internal/cmd/       service startup and route wiring
internal/controller/ HTTP controllers
internal/service/   business services and cron orchestration
manifest/config/    runtime configuration
manifest/sql/       schema, seed, and bootstrap SQL
pkg/                shared stable packages
```

## A concrete example: scheduled jobs

Scheduled job management is a good example of what stays in the host:

- handler registry
- persisted job lifecycle
- execution dispatch
- cleanup policies
- shell execution guardrails

Those are governance capabilities, not optional business modules.
