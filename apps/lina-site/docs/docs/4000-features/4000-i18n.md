## 概述

`LinaPro`内置了完整的国际化运行时，支持在请求级别动态切换语言，宿主和插件的语言资源统一管理，插件启用后语言包自动合并。

## 内置语言包

框架默认内置**英文（`en-US`）和简体中文（`zh-CN`）**两套完整语言包，包含所有宿主界面文案、菜单名称、错误信息和接口文档翻译。其他语言（如繁体中文、日文等）需要用户自行创建翻译文件并维护，框架本身不提供这些语言的默认翻译内容。

## 配置

在`config.yaml`中配置国际化行为：

```yaml
i18n:
  # 默认语言（请求未携带语言标识时使用）
  default: zh-CN
  # 是否开启多语言；关闭时前端隐藏语言切换按钮
  enabled: true
  # 语言列表（决定前端切换菜单的顺序和显示名称）
  # 注释某个语言即可停用
  locales:
    - locale: en-US
      nativeName: English
    - locale: zh-CN
      nativeName: 简体中文
```

## 目录结构

宿主语言资源位于`manifest/i18n/`目录下：

```text
apps/lina-core/manifest/i18n/
├── zh-CN/
│   ├── framework.json         # 框架基础文案
│   ├── menu.json              # 菜单名称
│   ├── dict.json              # 字典类型和字典数据名称
│   ├── config.json            # 系统参数相关文案
│   ├── error.json             # 错误信息
│   ├── job.json               # 定时任务相关文案
│   ├── notify.json            # 通知相关文案
│   ├── role.json              # 角色相关文案
│   ├── plugin.json            # 插件相关文案
│   ├── artifact.json          # 构建产物相关文案
│   ├── public-frontend.json   # 前端公共文案
│   └── apidoc/
│       ├── common.json        # 公共接口文档翻译（分页、时间戳等公共字段）
│       └── core-api-*.json    # 各模块接口文档翻译
└── en-US/
    └── （与 zh-CN 相同结构，英文翻译）
```

## 语言包格式

语言包使用`JSON`格式，支持嵌套结构（推荐）或扁平点分隔键：

```json
{
  "menu": {
    "dashboard": {
      "title": "工作台"
    },
    "iam": {
      "title": "权限管理",
      "user": {
        "title": "用户管理"
      }
    }
  },
  "framework": {
    "description": "面向可持续交付的 AI 原生全栈框架"
  }
}
```

**扁平键等价写法：**

```json
{
  "menu.dashboard.title": "工作台",
  "menu.iam.title": "权限管理"
}
```

框架在加载时会将嵌套`JSON`规范化为扁平键，两种格式混用时扁平键优先级更高。

## 插件国际化

每个插件在自己的`manifest/i18n/`目录下维护语言包，插件启用后宿主自动合并插件的语言资源：

```text
apps/lina-plugins/content-article/manifest/i18n/
├── zh-CN/
│   ├── content-article.json         # 插件运行时语言包
│   └── apidoc/
│       └── plugin-api-article.json  # 插件接口文档翻译
└── en-US/
    └── content-article.json
```

插件语言包文件使用插件`ID`命名（`kebab-case`），避免与宿主和其他插件的键名冲突：

```json
{
  "plugin": {
    "content-article": {
      "article": {
        "title": "文章管理",
        "status": {
          "draft": "草稿",
          "published": "已发布"
        }
      }
    }
  }
}
```

## 添加新语言

添加新语言只需三个步骤，**不需要修改任何`Go`代码、`SQL`或前端`TypeScript`文件**：

**第一步：在`config.yaml`中注册语言**

```yaml
i18n:
  locales:
    - locale: ja-JP
      nativeName: 日本語
```

**第二步：创建语言资源目录**

```bash
mkdir -p apps/lina-core/manifest/i18n/ja-JP/apidoc
```

**第三步：创建翻译文件**

在`manifest/i18n/ja-JP/`下创建对应的`JSON`翻译文件，复制中文或英文版本作为模板，翻译各条目内容。

重启服务后，管理工作台语言切换菜单中会自动出现日文选项。

## 翻译缓存管理

运行时语言包在首次请求时加载到内存缓存，修改翻译文件后需要使缓存失效才能生效。

**重启服务（开发环境）：**

```bash
make stop && make dev
```

**运行时缓存失效（生产环境，无需重启）：**

框架提供了按范围失效的`API`，在管理工作台的系统接口中可以触发。缓存失效的范围粒度：

| 范围 | 说明 |
|------|------|
| 特定语言 | 只失效指定`locale`的缓存 |
| 特定插件 | 只失效指定插件的翻译缓存 |
| 宿主全量 | 失效宿主所有语言的缓存 |

:::tip
不要无理由清空所有语言和所有扇区的翻译缓存，这会导致短暂的翻译抖动。按最小必要范围失效，减少对用户的影响。
:::

## 前端语言切换

前端管理工作台在页面右上角提供语言切换控件，点击后立即切换界面语言。语言选项来自`i18n.locales`配置。

当`i18n.enabled: false`时，前端隐藏语言切换控件，所有文案使用`i18n.default`指定的默认语言。

## 接口文档翻译

接口文档（`/api.json`）的描述文本也支持多语言翻译（没有翻译时默认为英文），翻译文件放在`apidoc/`子目录下：

```json
// manifest/i18n/zh-CN/apidoc/core-api-article.json
{
  "plugins": {
    "content-article": {
      "article": {
        "list": {
          "summary": "文章列表",
          "description": "分页查询文章列表，支持按状态筛选",
          "params": {
            "page": "页码",
            "pageSize": "每页数量"
          }
        }
      }
    }
  }
}
```

`en-US`的接口文档翻译目录通常保留为空占位，以英文源码注释作为默认文案。

## 语言代码规范

`LinaPro`使用标准`IETF BCP 47`语言代码，例如：

| 语言 | 代码 |
|------|------|
| 简体中文 | `zh-CN` |
| 繁體中文 | `zh-TW` |
| 英文 | `en-US` |
| 日文 | `ja-JP` |
| 韩文 | `ko-KR` |

配置文件的目录名、`config.yaml`中的`locale`字段、前端`locale`参数均使用这套代码，保持一致。
