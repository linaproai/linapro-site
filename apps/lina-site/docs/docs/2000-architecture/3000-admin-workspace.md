## 概述

`lina-vben`是`LinaPro`内置的默认管理工作台，基于`Vue 3 + Vben5 + Ant Design Vue + TypeScript`构建。它是`lina-core`宿主`API`和所有插件`API`的标准`UI`表达层。

开发者可以直接在工作台基础上构建业务应用，也可以通过插件机制按需扩展或替换任意模块，甚至可以完全替换为自定义的前端工作台。

```mermaid
graph TB
    subgraph FE["前端层"]
        WS["lina-vben<br/>管理工作台"]
    end

    subgraph BE["宿主层 (lina-core)"]
        direction LR
        Auth["认证 & 鉴权"]
        MenuSvc["菜单治理"]
        PluginEngine["插件引擎"]
    end

    subgraph PL["插件层"]
        direction LR
        SP["源码插件<br/>multi-tenant / org-center<br/>monitor-* / content-notice"]
        DP["动态插件 (WASM)"]
    end

    DB[("数据库<br/>PostgreSQL / SQLite")]

    WS -->|"REST API"| BE
    BE --> PL
    BE --> DB
    PL --> DB
```

## 功能模块

`lina-vben`的全部功能模块均在此列出，其中部分模块由官方插件提供，安装并启用对应插件后，菜单自动注入工作台，无需修改工作台代码。

### 权限管理

**用户管理**

| 功能 | 说明 |
|------|------|
| **用户列表** | 分页展示，支持按用户名、手机号、状态筛选 |
| **创建用户** | 设置用户名、密码、角色、手机号、邮箱等基础信息 |
| **编辑用户** | 修改用户信息、重置密码、调整角色分配 |
| **状态管理** | 启用/禁用用户账号，禁用后立即失效 |
| **批量导出** | 导出用户列表为`Excel`文件 |

**角色管理**

| 功能 | 说明 |
|------|------|
| **角色列表** | 展示所有角色，包含角色描述和用户数量 |
| **创建角色** | 定义角色名称和描述 |
| **权限分配** | 树形勾选菜单权限（目录/菜单/按钮三级） |
| **权限生效** | 权限拓扑变更后快速生效（单机即时、集群最长3秒），无需用户重新登录 |

**菜单管理**

| 功能 | 说明 |
|------|------|
| **菜单树** | 展示完整的菜单层级结构 |
| **菜单类型** | 支持目录（`D`）、菜单（`M`）、按钮（`B`）三种类型 |
| **动态配置** | 菜单路径、组件、图标、排序均可在管理界面调整 |
| **权限标识** | 按钮类型菜单绑定权限标识，用于`RBAC`鉴权 |

**RBAC 权限模型**

```mermaid
graph LR
    User["用户"] -->|"归属"| Role["角色"]
    Role -->|"勾选"| Menu["菜单<br/>(目录 / 页面 / 按钮)"]
    Menu -->|"绑定"| Perm["权限标识<br/>system:user:list"]

    API["API 请求<br/>(JWT Token)"] --> Check["权限校验"]
    Check -->|"读取用户角色"| Role
    Check -->|"比对权限标识"| Perm
    Check -->|"✓ 通过"| Pass["正常响应"]
    Check -->|"✗ 拒绝"| Deny["403 Forbidden"]
```

### 多租户管理

> 需要安装并启用官方插件 `multi-tenant`。未安装时，宿主回退到单租户模式（`tenant_id = 0`），开箱即用不受影响。

`LinaPro`框架在宿主层面原生内置了多租户基础设施，包括租户中间件、`bizctx`租户身份、租户感知缓存作用域和插件治理字段等稳定接缝。`multi-tenant`插件在此基础上提供完整的租户管理控制台与生命周期治理能力。

**租户管理**

| 功能 | 说明 |
|------|------|
| **租户列表** | 分页展示所有租户，支持按名称、状态筛选 |
| **新增租户** | 创建租户并完成初始化开通流程 |
| **编辑租户** | 修改租户基本信息和配置 |
| **生命周期管理** | 支持租户的启用、禁用和删除，并执行对应的生命周期钩子 |
| **租户代管** | 平台管理员可以以租户身份进入工作台，便于排查租户问题 |

**租户插件治理**

每个租户可独立控制`tenant_scoped`类型插件的启用状态，实现租户级插件按需开通：

| 功能 | 说明 |
|------|------|
| **插件列表** | 查看当前租户可用的插件列表及其启用状态 |
| **启用插件** | 为当前租户开通指定插件能力 |
| **禁用插件** | 为当前租户关闭指定插件能力 |

**多租户策略**

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 隔离模型 | `pool` | 基于`tenant_id`列的共享数据库隔离 |
| 用户租户基数 | `multi` | 一个用户可同时归属多个租户 |
| 解析器链 | `override → jwt → session → header → subdomain → default` | 按顺序尝试解析当前请求的租户上下文 |
| 歧义处理 | `prompt` | 无法明确判断租户时，返回租户选择提示 |

**租户解析流程**

```mermaid
flowchart LR
    Request["HTTP 请求"] --> Chain

    subgraph Chain["租户解析器链（依次尝试）"]
        direction TB
        R1["override（显式覆盖）"] --> R2["jwt（Token 中的 tenant_id）"]
        R2 --> R3["session（会话缓存）"]
        R3 --> R4["header（X-Tenant-ID）"]
        R4 --> R5["subdomain（子域名）"]
        R5 --> R6["default（回退 tenant_id = 0）"]
    end

    Chain -->|"解析成功"| CTX["bizctx 注入<br/>租户上下文"]
    CTX --> Filter["tenant_id 列过滤<br/>Pool 隔离模型"]
    Filter --> DB[("共享数据库<br/>PostgreSQL")]
```

### 扩展中心

**插件管理**

插件管理是`LinaPro`扩展能力的控制台：

| 功能 | 说明 |
|------|------|
| **插件列表** | 展示所有已发现的插件，包含类型（源码/动态）、版本、状态 |
| **安装** | 将插件从「已发现」状态变为「已安装」，执行安装`SQL`和初始化流程 |
| **启用/禁用** | 切换插件的运行状态，禁用后菜单和路由立即隐藏 |
| **卸载** | 将插件彻底移除，提供「保留数据」和「清理数据」两种选项 |
| **上传动态插件** | 上传`WASM`格式的动态插件包（`.wasm`文件） |
| **版本管理** | 查看插件当前版本和可用升级版本 |

### 开发中心

**接口文档**

宿主在启动时自动扫描宿主和所有已启用插件的接口，生成统一的在线`API`文档：

- 支持在线浏览所有接口的请求参数和响应结构
- 支持直接在页面上发起`API`调试请求
- 文档内容实时反映当前已启用的插件能力

**系统信息**

| 信息项 | 说明 |
|--------|------|
| `CPU`使用率 | 当前服务器`CPU`负载 |
| 内存使用 | 已使用内存和总内存 |
| 磁盘信息 | 各磁盘分区使用情况 |
| 运行时信息 | `Go`运行时版本、`Goroutine`数量等 |

## 插件菜单动态注入原理

插件菜单不是硬编码在工作台代码中的，而是通过以下机制动态注入：

```mermaid
sequenceDiagram
    participant WorkSpace as 管理工作台
    participant Core as lina-core
    participant Plugin as 源码插件

    WorkSpace->>Core: GET /api/v1/menu（请求菜单）
    Core->>Plugin: 触发 menu.filter 钩子
    Note over Plugin: 检查插件是否已启用
    Plugin-->>Core: 注入插件菜单项到菜单树
    Core-->>WorkSpace: 返回完整菜单树（含插件菜单）
    WorkSpace->>WorkSpace: 渲染侧边栏
    Note over WorkSpace: 插件菜单组件路径<br/>通过 dynamic-page 壳加载
```

当插件被禁用时，工作台调用菜单接口不会包含该插件的菜单项，用户界面上对应入口自动消失，无需重新部署或刷新配置。
